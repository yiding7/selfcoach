# Health Assistant · 健身教练 / 营养师 / 健康顾问 一体化 AI 工具

> 一套**模型无关、即启即用**的个人健康基建。
> 训练数据自动同步 → 确定性引擎算出同部位对比与下次训练处方 →
> 生成图文并茂的自包含周/月/年报 → 由你接入的任意模型套上教练人格来讲解。

**English** → [README.en.md](README.en.md)

---

## 它和别的健身工具有什么不同

**换模型不换结果。** 所有分析、指标、图表都由确定性 Python 脚本产出。
模型只负责把结论讲得好听，不负责算数。你今天用 Claude、明天用 GPT、
后天用本地 Ollama，报表里的吨位、估算 1RM、对比结论**完全一致**。

这不是实现细节，是设计目的：健康记录的价值在于纵向可比。
如果数字是模型算的，换个模型历史就没法对照了。

**零依赖。** 只用 Python 标准库。不需要 `pip install`，不需要 matplotlib，
clone 下来就能跑。

**零外链。** 生成的 HTML 把图表以内联 SVG 写死在文件里。
断网能看，存档十年后还能看，Cmd+P 直接存 PDF，深浅色自动跟随系统。

**有没有训记都能用。** 有训记 API key 就自动同步；没有就用自然语言手记，
分析功能一模一样。

## 5 分钟上手

```bash
git clone <your-fork-url> health-assistant
cd health-assistant
./install.sh              # 建目录、把 skills 链到你的 agent 宿主。不下载任何东西
cp .env.example .env      # 有训记就填 key；没有就跳过
./scripts/hc doctor       # 体检：环境、凭证、本地数据
```

然后走两条路之一：

**有训记**
```bash
./scripts/hc sync --since 30d     # ⚠️ 训练接口 30 秒/天限频，30 天约 15 分钟
./scripts/hc report weekly
```

**没有训记**
```bash
./scripts/hc log                  # 输入速记，Ctrl-D 结束
./scripts/hc report weekly
```

之后在 Claude Code / Codex / Cursor 里直接说「帮我看看这周练得怎么样」就行。

## 核心功能

### 同部位对比

一次训练里通常混着好几个部位，所以对比是在**肌群粒度**做的，不是整次训练笼统地比。

```
$ hc compare --group 背

「背」本次 vs 上次
  依据：上一次练「背」是 2026-06-28（7 天前，背 18 组 vs 本次 17 组）

  有效组数   18 → 17 组 ↓ -5.6%
  总容量     5800 → 6044 kg ↑ +4.2%
  顶组负荷   40.0 → 50.0 kg ↑ +25.0%   （仅比共同动作）

  逐动作（3 个动作两次都做了）
    宽距高位下拉   顶组 40.0 → 40.0kg =   总次数 26 → 48 次 ↑ +84.6%
    器械划船2      顶组 40.0 → 50.0kg ↑ +25.0%

优点
  ✓ 背 的最强单组估算 1RM 从 53.3kg 提升到 60.0kg（+12.5%），力量在往上走。
  ✓ 宽距高位下拉 同样的重量下总次数 26 → 48 次，这是加重之前该走的一步。
```

**两次没有共同动作时，工具拒绝比较峰值负荷**，并解释为什么 ——
器械推胸的 40kg 和俯卧撑折算的 51kg 不是一回事，硬比会得出
「力量下降 20%」这种既错误又打击人的结论。

### 下次训练处方

双重递进（先加次数，到区间上限再加重），外面套护栏：

```
$ hc next 背
动作              组     重量    目标次数  调整
宽距高位下拉        5   42.5kg     5-8   加重 +2.5kg
引体向上（辅助）     1        —     5-8   减少辅助配重
器械划船2          4   50.0kg     5-8   保持重量，目标 +1 次
```

护栏包括：周容量超过可恢复上限就不加、**处在明显减重期时以保强度为主而不是催加重**、
辅助器械的进步方向是把配重往下调（不是加重）。

### 报表

`hc report weekly | monthly | yearly` 产出两个文件：

- `2026-W28.html` —— 完整可读的自包含报告
- `2026-W28.facts.json` —— 算好的事实，给模型写叙述用

**没有模型时报告依然完整**（数据、图表、对比、处方全在，只是少了教练的话）。
有模型时让它读 facts.json 写叙述，再 `hc inject` 注入。

图表包括：部位组数堆叠柱、各部位训练量 vs 个体化参考区间、
人体肌群热力图（正反面）、体重 7 日均线 + 每日散点、训练日历热力图。

## 没有训记怎么办

这是**一等公民路径**，不是降级方案。

对助手说：
> 今天练胸。卧推 60kg 做了 10/10/8，上斜哑铃 22.5kg 三组 12 个，最后一组挺吃力

助手转成速记给你确认，确认后落库：

```
# 2026-07-26 胸
杠铃卧推 60x10 60x10 60x8@8
上斜哑铃卧推 22.5x12x3
```

之后的同部位对比、下次处方、周月年报，跟训记同步来的数据**享受完全相同的分析**。

速记语法（也可以直接手写）：

| 写法 | 含义 |
|---|---|
| `60x10` | 60kg 做 10 次 |
| `22.5x12x3` | 22.5kg 做 12 次，共 3 组 |
| `~40x10` | 热身组，不计入有效容量 |
| `62.5x8@8` | RPE 8 |
| `BWx12` / `BW+10x8` | 自重 / 自重加 10kg |
| `T:60s x3` | 计时 60 秒，3 组 |
| `L:20x10 R:22.5x10` | 单侧，分别记左右 |
| `> 睡眠不足` | 整次训练的备注 |

## 关于训记同步的耗时（重要）

**训记训练接口一天只能查一天，且限频 30 秒。**这不是可以优化掉的常数。

| 范围 | 首次耗时 |
|---|---|
| 30 天 | ≈ 15 分钟 |
| 90 天 | ≈ 45 分钟 |
| 1 年 | ≈ 3 小时 |

所以设计上：

- **抓过的日期永不重抓**（空日期也记录）。第二次跑同样范围是零请求、瞬间完成。
- **原始响应原样落盘。** 改了解析逻辑跑 `hc rebuild` 离线重算，一次网络请求都不用。
- **随时 Ctrl-C 安全**，进度已保存，下次接着来。
- 补历史用 `--budget-minutes 20` 分批跑，适合放进 cron。

本地缓存很贵，换设备时用 `data/` 目录带走，别重新拉。

## 命令一览

```bash
hc doctor                      # 环境体检
hc sync [train|body|food]      # 从训记同步
hc rebuild                     # 用原始缓存离线重算，零网络
hc log                         # 手记训练
hc sessions --since 30d        # 列出本地训练
hc summary --date 2026-07-12   # 单次训练详细指标
hc compare [--group 胸]         # 同部位对比
hc next 胸                      # 下次训练建议
hc report weekly|monthly|yearly
hc inject <报告名> --slot opening
hc classify [--unknown-only]   # 查看/教会动作的肌群归属
```

## 隐私

- 四把训记 API key 只存在 `.env`（已 gitignore）。任何脚本、日志、报告都不会打印。
- `data/`（训练记录、体重、饮食、个人档案）**默认不进版本库**。
- 接 LLM 适配器做无人值守报告时，**只发送聚合后的 findings**，
  原始餐食、用药、体检数值不出本机。
- 想跨设备同步私人数据：在 `data/` 里单独 init 一个私有仓库。

## 设计上的几条硬规矩

这些都有测试保证：

1. **每条「缺点」必须挂着一条带数字的「改进点」。** 批评不会孤零零出现。
2. **每条「优点」必须有数字支撑。** 没有 metrics 的优点在构造时直接抛异常。
3. **报告 HTML 里不允许出现任何外链。**
4. **RPE 覆盖率不足 30% 时，所有依赖主观强度的结论一律不输出**，而不是猜一个。
5. **缺少可选能力不是错误。** 非零退出码只留给真正的故障。
