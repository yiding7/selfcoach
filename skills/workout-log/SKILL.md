# 记录训练

## 分工（重要）

- **自然语言 → 速记文本**：你来做。模型擅长这个，而且结果会展示给用户确认。
- **速记文本 → 结构化数据**：解析器来做。确定性、有单元测试。

你**不要**自己把数据写进 JSON。把口述转成速记，让 `hc log` 去解析。
这样「六十公斤四组」变成 `60x10x4` 这一步出错时用户一眼能看见。

## 绳索类动作：先确认口径，再记数字

面拉、三头下压、绳索夹胸、高位下拉这类**滑轮组**动作，配重片上的数字取决于
机器的传动比 —— 同一个动作换台机器，标称 40 kg 和 18 kg 可能是同一个力。

用户报这类动作时：

- 如果他之前记过同一个动作、这次数字**变化超过 30%**，问一句是不是换了机位，
  不要默认是力量变化
- 口径和怎么测传动比，见 **`knowledge/measurement/load-measurement.md`**。结论是
  **记手上的力（标称 ÷ 传动比）**，不是记配重片读数
- 已经混过口径的历史数据**不要回头改** —— 划一条起算线记进
  `profile/personal-context.md`，之前的只当量级参考

## 流程

1. 用户口述：「今天练胸，卧推60公斤4组8到10个，最后一组有点吃力，还做了绳索夹胸15公斤三组15个」
2. 你转成速记，**先展示给用户看**：

```
# 2026-07-26 胸
杠铃卧推 60x10 60x10 60x9 60x8@9
绳索夹胸 15x15x3
```

3. 用户确认后执行：

```bash
./scripts/hc log --yes <<'LOG'
# 2026-07-26 胸
杠铃卧推 60x10 60x10 60x9 60x8@9
绳索夹胸 15x15x3
LOG
```

不确定时先 `--dry-run` 看解析结果。

## 速记语法

```
# 2026-07-26 推日 19:05-20:20    日期 标题 起止时间（都可省略）
杠铃卧推 ~40x10 60x10 62.5x8@8   ~ 是热身组，@8 是 RPE
上斜哑铃卧推 22.5x12x3            一个重量做三组
双杠臂屈伸 BWx12 BW+10x8          BW = 自重，BW+10 = 自重加 10kg
平板支撑 T:60s x3                 计时组
保加利亚分腿蹲 L:20x10 R:22.5x10   单侧，分别记左右
> 睡眠不足                        整次训练的备注
```

## 几个要主动问的点

- **重量单位**：默认 kg。用户说「135磅」要换算并说明。
- **单侧动作**：哑铃弯举这类，用户说的重量通常是**单只手**的。确认一下。
- **RPE**：不用每组都问。但可以顺口问一句最后一组的感觉，
  「最后一组还能再做几个？」→ 还能做 2 个 ≈ RPE 8。
  这是低成本高价值的信息，但**不要变成盘问**，用户不想说就算了。
- **动作名**：尽量用训记标准中文名，方便和同步来的数据配对。
  不确定就用用户的说法，分类器能靠关键词认出大部分。

## 去重

同一天如果已经有训记同步来的记录且动作高度重合，工具会提示并把手记标记为
「已被取代」—— **不会删除**。这是刻意的：用户的记录不该被工具丢掉。

## 分类失败时

如果 `hc classify --unknown-only` 显示有认不出的动作，问用户它练的是哪个部位，
然后 `hc classify --learn '动作名=部位'`。教一次，以后都认得。
