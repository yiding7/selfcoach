# 身体数据

## 最重要的一条：看趋势不看单日

实测这个账号 7 月的体重日间波动可达 **±1.8kg**
（7/14 是 79.8，7/16 是 81.6，7/18 是 80.0）。

**永远用 7 日移动均线说话。** 拿单日读数做任何判断都会得出垃圾结论。
`hc` 里所有涉及体重的计算都已经用均线，你在叙述时也要这么说。

## 命令

```bash
./scripts/hc sync body --since 90d    # 从训记同步（范围查询，一次调用，很快）
./scripts/hc doctor                   # 看最新体重
./scripts/hc report weekly            # 报告里有体重趋势图
```

## 写入身体数据

训记的写入接口是两步的，**不能跳过**：

1. 先 `dry_run: true` 请求，拿到摘要
2. 把摘要**展示给用户**，等他明确确认
3. 再用 `dry_run: false` + `confirmed: true` 写入

缺少 `confirmed` 时服务端会直接拒绝。这是设计如此，不要试图绕过。

## 围度：先看测量规程

**`knowledge/measurement/measurement-protocol.md`** 是围度测量的唯一真相源：量在哪、怎么读数、
腰高比和 Navy 体脂估算怎么算、常见误差源有多大。用户问「腰围量哪儿」
「体脂怎么估」一律照它答，不要自己临场编方法。

两条最容易忘的：

- **一致性 > 精度。** 换测量者能差 1–3 cm，比半年的真实变化还大。
  `data/body/` 的围度记录**可以**带 `source`（参考字段，不强制）。
  带了就别把不同 `source` 的读数逐点比较；没带就当来源不明，同样别和自测值混比。
- **Navy 公式对颈围敏感** —— 颈围差 1 cm，体脂估算差约 0.7 个百分点。
  颈围换了测量者，整条估算序列作废，要重新起算。

## 字段名的坑

腰围的字段名是 **`weist`**、臀围是 **`bot`**（训记的历史拼写）。
不要"修正"成 `waist` / `hip` —— 改了写回时会对不上字段，
而且 `hip` 已经被**胯围**占用了（胯围在髂嵴，比臀围高，是另一个数）。
完整的 `type` 取值表见 `data-map.md`。

## 平台期

体重连续两周均线持平不一定是平台期，可能是：
- 水分潴留（高盐、高碳水、训练后炎症反应）
- 肌肉量增加抵消了脂肪下降
- 记录不完整

判断前先看围度和训练表现。如果力量还在涨、围度在降，那不是停滞。

## 目标可达性

如果目标日期和当前趋势明显对不上，**温和但诚实地说出来**，
并给一个基于当前速度的现实日期。不要假装还能达成，也不要说教。

安全的减重速度一般是每周 0.5–1% 体重。超过这个范围要提醒
（见 `safety-boundaries.md`），涉及用药一律转医生。
