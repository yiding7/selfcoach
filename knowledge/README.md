# knowledge/ —— 通用知识

这里放**任何人都能用**的东西：教练怎么说话、动作怎么分类、嘌呤谁高谁低。
不放任何属于某一个人的东西 —— 那些在 `profile/` 和 `data/`。

这条分界线决定了这个仓库能不能安全地公开分享，所以它是硬的：
**`knowledge/` 里出现名字、病史、体检数值，就是放错地方了**
（`tests/test_persona.py` 会检查这一点）。

## 五个区

| 目录 | 谁读 | 放什么 |
|---|---|---|
| `coach/` | **模型读** | 人格核心、四种语气、医疗安全边界、能力矩阵 |
| `measurement/` | **模型读** | 怎么量：围度测量规程、负荷计量口径（绳索传动比）|
| `movements/` | 脚本读 | 动作分类、动作模式、结构平衡规则 |
| `training/` | 脚本读 | 周容量参考区间、心率区间、自重系数 |
| `nutrition/` | 脚本读 | 菜品候选池、配比表、食材营养、嘌呤实测值 |

分区的依据就是这个项目最核心的那条规矩 —— **数字归脚本，措辞归你**。
`coach/` 和 `measurement/` 是散文，模型直接读；后三个是确定性数据表，
只有 `hc` 命令读，模型不要凭印象改里面的数。

改数据表之前先看一眼 `tests/`：`purine-reference.json`、`dish-composition.json`
这些都有内容契约测试（配比要加满 100、食材名要在参考表里存在）。

## 你自己的资料放哪

**两个位置，按「这批资料是不是一个整体」分：**

- **一整套现成的知识库**（买来的课程包、别人整理好的资料库）→
  直接放 `knowledge/` 根，**保持原样不用拆**
- **零散的单份资料**（一篇论文、一份讲义、自己的笔记）→
  `knowledge/library/` 下按主题挑一个目录；不确定就丢 `library/notes/`

```
knowledge/library/
  INDEX.md      ← 你维护的总目录，助手每次先读它
  nutrition/ training/ cardio/ recovery/ reference/ notes/
```

`library/` 整个在 `.gitignore` 里，只有目录骨架和 README 会提交。
详细约定、**以及各种文件格式要不要装依赖**，见
[`library/README.md`](library/README.md)。

> **`knowledge/` 根目录是白名单。** `.gitignore` 只放行上面五个区、`library/`
> 和本文件，其余一律忽略。所以整套资料丢在根上**不会被误提交** ——
> 这正是白名单的用处：放错位置的后果是「被忽略」，而不是「被公开」。

## 给自己的知识库加索引（可选，但很值）

一套资料丢进来之后，助手面对的是一个陌生目录。没有索引它只有两个选择：
**通读**（大 PDF 会把上下文挤爆，几百份根本读不完）或者**瞎猜**（按文件名猜内容，
经常猜反）。索引就是为了让它有第三个选择：**先看目录，再只打开需要的那两三份**。

### 让助手自己生成

不用手写。直接说：

> 查找 `knowledge/某某知识库/` 下的文件，写一份索引

它会做四件事：

1. **扫目录**，统计份数和格式分布
2. **做依赖体检** —— 哪些格式当场读得了、哪些要装东西（PDF 要 poppler）。
   **只在这一刻问你装不装**，而且你说不装它也照样把索引写完，
   只是把那些标成读不了
3. **抽样读**，给每份写一句「这份能回答什么问题」。读不了的就照文件名和
   目录结构推，并**明确标注是推的**
4. 写成 `<那个目录>/索引.md`，并在 [`library/INDEX.md`](library/INDEX.md) 里加一行指过去

也可以只索引一部分：「只给 `优质文献/` 那个子目录建索引」。
资料后来又加了：「更新一下那份索引，只补新增的」。

### 索引长什么样

下面这份是**给模型检索用**的格式，不是给人看的目录。六个部分，
每一部分都在解决模型的一个具体失败模式：

````markdown
# 某某知识库 —— 索引

> 位置：`knowledge/某某知识库/`（整套保持原样，不拆分类）。
> 共 186 份。生成于 2026-08-11。
> **以磁盘上的真实路径为准** —— 原库自带的编号体系和路径对不上，
> 而助手唯一能用来打开文件的就是路径。

## 怎么用这份索引

1. 先扫「按主题定位」，找到相关的两三份
2. 再去「完整清单」核对路径和格式
3. **只打开那几份。不要通读整个目录。**

引用时说清出处（哪一份、哪一讲）。要证据等级就去 `优质文献/`，
科普短文是二手转述，别当文献结论引。

## 格式与可读性

| 标记 | 格式 | 份数 | 依赖 |
|---|---|---|---|
| ✅ | `.docx` | 80 | 不用装 —— zip+XML，标准库解 `word/document.xml` |
| ⚙️ | `.pdf` | 100 | **要 poppler**（`brew install poppler`）。没装一页也读不出来 |
| — | `.mp3` | 5 | **不解析**，当备份。内容和讲义重合，要查看讲义 |

> ⚠️ **docx 里的图片读不到。** 这批讲义截图很多，摘要提到的数字在正文里
> 找不着多半就在图里 —— 那时候要说「关键内容在图里，我读不到」，不要猜。

## 按主题定位

### 热量缺口 · 减肥总原理
- ✅ `《科学减肥二十五讲》/03 第三讲 热量缺口从哪里来？.pdf`
- ✅ `优质文献/国际运动营养学会（ISSN）立场声明：饮食与身体成分.pdf`

### 抗阻训练变量（组数 / 频率 / 顺序 / 力竭）
- ✅ `优质文献/系统综述：力竭对增力＆增肌的影响.pdf`
- ✅ `优质文献/系统综述：抗阻训练顺序对增肌＆增力的影响.pdf`

## 完整清单

### `优质文献/`（49 份）
研究文献：系统综述、RCT、学会立场声明。**要证据等级的时候来这里。**

| | 文件 | 一句话 |
|---|---|---|
| ✅ | `系统综述：力竭对增力＆增肌的影响.pdf` | 力竭非必要；有训练经验者的肌肥大略优 |
| ✅ | `系统综述：抗阻训练频率对增肌的影响.pdf` | ⚠️ **中文标题写「增肌」，原文测的是力量** —— 别当肥大证据引　*(读原文摘要提炼)* |

## 已知的坑

- 中文标题是转述，**和原文结论不完全一致**，上面标了 ⚠️ 的那几条尤其
- `小红书科普文章汇总/` 是二手转述，不能当文献引
````

### 六个部分各自在防什么

| 部分 | 防的失败模式 |
|---|---|
| **路径声明** | 索引里的编号/标题和磁盘对不上，助手拿着索引却打不开文件 |
| **怎么用** | 助手一头扎进去通读，上下文被大 PDF 挤爆 |
| **格式与可读性** | 读不了的文件被当成读过；以及**该提醒装依赖时提醒不了** |
| **按主题定位** | 只有文件清单时，助手得逐条读标题去猜，又慢又容易漏 |
| **完整清单** | 找到主题之后核对不了确切路径和格式 |
| **已知的坑** | 标题党、二手转述、图里的数字 —— 这些不写下来，每次都会重新踩 |

### 写索引的三条硬规矩

这三条是索引有没有用的分水岭：

1. **一句话写「这份能回答什么问题」，不是复述标题。**
   「蛋白质摄入指南」等于没说；「不同训练量下的蛋白需求、分配时机，
   回答『我该吃多少蛋白』『练后必须马上补吗』」才有用。
2. **区分「读过」和「没读」。** 读了原文提炼的标 `*(读原文摘要提炼)*`；
   靠文件名推的要说明是推的。**读不了的文件绝不编摘要** ——
   一条编出来的摘要会让人（和下一个模型）以为这份资料已经被消化过了。
3. **主题索引和完整清单里的路径要重复写。** 这里故意不 DRY ——
   检索时少跳一次目录，就少一次读错文件的机会。

### 能读什么、要装什么（详见 [`library/README.md`](library/README.md)）

| | 格式 | 依赖 |
|---|---|---|
| ✅ | `.md` `.txt` `.csv` `.json` `.docx` `.xlsx` `.pptx` `.epub` 图片 | **不用装** —— docx/xlsx 是 zip+XML，标准库就能解 |
