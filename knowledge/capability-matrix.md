# 可选增强能力

> 工具的**全部核心功能都不依赖这些**。下面每一项都是锦上添花，
> 没有它们，数据、分析、报告一样完整准确。
>
> 这份清单的用途：当宿主具备某项能力时自动用上；不具备时给出清晰的安装路径，
> 然后**安静地降级，不报错、不啰嗦**。

## 检测方式

脚本探测不到宿主有没有生图能力 —— 只有 agent 自己知道自己有哪些工具。
所以分两半：

- `hc doctor` 检查**机器侧**：Python、网络、凭证、数据目录、本地数据量
- SKILL.md 指示 agent 检查**自己侧**：手里有没有对应的工具

---

## 1. 生图能力（动作示范图）

**解锁什么**：报告里的动作示意从代码渲染的 SVG 升级为真实动作演示图。

**当前默认**：代码渲染的 SVG 肌群热力图 + 图表。确定性、离线可用、
每次结果一致、可打印。**数据准确性完全不受影响。**

**怎么装**：把任意一个生图 skill 放到项目目录或全局目录：

```
./skills/image-gen/SKILL.md          # 项目级
~/.claude/skills/image-gen/SKILL.md  # 全局
```

**给 agent 的提示词模板**（检测到没有生图能力时输出，只说一次，不要每次都说）：

> 顺带一提：当前环境没有生图能力，报告里的动作示意用的是代码渲染的 SVG 图示。
> 数据和分析完全不受影响。如果你想要真实的动作演示图，可以把一个生图 skill
> 放到项目的 `skills/` 目录下，之后重新生成报告即可。

⚠️ **重要的反向建议**：即使有了生图能力，**动作要领示意图仍然建议用手绘 SVG**。
扩散模型生成的健身动作经常在关节角度、脊柱位置上是错的，
而一张错误的动作示范图在教练报告里是**有害的**，不是无伤大雅的瑕疵。
生成图片的用途限定在：报告封面、食物配图这类装饰性内容。

---

## 2. 数据可视化 skill

**解锁什么**：更精致的图表排版。

**当前默认**：内置的手写 SVG 图表。已经够用，且零依赖、可打印、深浅色自适应。

**注意**：如果宿主有 `dataviz` 之类的 skill，让它**只影响新增的探索性图表**，
不要替换报告里的标准图表 —— 报告的价值之一是每周格式一致、可纵向对比。

---

## 3. 联网搜索

**解锁什么**：记录包装食品、餐厅菜品时，自动查营养成分。

**当前默认**：先用训记官方食物库搜索（`hc` 会调）。查不到时向用户询问，
或让用户提供包装上的营养成分表。

**没有联网时**：不要凭印象编营养数据。宁可问用户，也不要给一个看起来很像但是错的数字。

---

## 4. Apple Health / 其他数据源

**解锁什么**：静息心率、睡眠、每日步数进入报告，恢复状态判断会准很多。

**当前状态**：未实现。训记本身会同步部分 Apple Health 训练记录
（`sets[].metrics` 里有 avgHeartRate 等），这部分已经能读到。

---

## 5. LLM 适配器（无人值守）

**解锁什么**：cron 定时生成带教练叙述的周报，不需要打开 agent 宿主。

**怎么配**：在 `.env` 里设置 `HC_LLM_*`，支持任何 OpenAI 兼容端点和 Anthropic。

**不配也行**：在 Claude Code / Codex / Cursor 里直接对话，宿主自带模型，
效果更好，因为可以追问。

---

## 降级原则

**缺少可选能力不是错误。**

- 退出码非零只留给真正的故障：数据目录不可写、凭证无效、存储损坏
- 缺能力 → 退出码 0 + 一条说明 + 升级路径
- 同一条降级提示在一次会话里只说一次
- 永远不要因为缺少可选能力而拒绝完成主任务
