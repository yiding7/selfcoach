# 知识库（私有资料区）

放你自己的专业资料：减脂指导、营养学教材、教练课程笔记、动作讲解、论文摘录。

**这个目录的内容不进版本库**，只有你本机有。仓库里只保留这份 README 和目录结构，
所以别人 clone 下来会得到一个空的、可以填自己资料的架子。

---

## 资料放哪

**两个位置，按「这批资料是不是一个整体」来分：**

| 情况 | 放哪 | 例子 |
|---|---|---|
| **一整套现成的知识库**，自带结构，不想拆 | 直接放 `knowledge/` 根，**保持原样** | 买来的课程包、别人整理好的资料库 |
| 零散的单份资料 | `knowledge/library/` 下按主题挑一个目录 | 单篇论文、一份讲义、自己的笔记 |

放在 `knowledge/` 根上是**安全的**：那一层做了 `.gitignore` 白名单，
只有 `coach/ measurement/ movements/ training/ nutrition/ library/` 和 `README.md`
会进版本库，别的一律忽略。所以整套资料丢在根上不会被误提交。

**不确定就放 `knowledge/library/notes/`**，回头再挪。别为了「先分好类」卡住。

```
knowledge/library/
  INDEX.md          ← 你维护的总目录（助手先读这个）
  nutrition/        营养、饮食结构、食物选择
  training/         训练方法、动作、周期化
  cardio/           有氧、心率、能量系统
  recovery/         睡眠、疲劳管理
  reference/        原始资料：PDF、电子书、课程讲义、论文
  notes/            你自己的读书笔记和摘录 —— **也是「先扔这儿」的落点**
```

目录不是强制的，按你顺手的来。只有一条是重要的：**维护 `INDEX.md`**，
新加了一整套知识库就在 `INDEX.md` 里加一行指过去。

## 为什么 INDEX.md 是关键

助手不会把整个目录读一遍 —— PDF 很大，全读会挤掉真正要紧的上下文。
它的实际流程是：

1. 先读 `INDEX.md`，看有哪些资料、各自讲什么
2. 判断当前问题跟哪一份相关
3. 只打开那一份

所以 `INDEX.md` 里每条写清楚**这份资料能回答什么问题**，比写标题有用得多。

### INDEX.md 的格式

```markdown
# 知识库总目录

## 营养
- `nutrition/蛋白质摄入指南.md` —— 不同训练量下的蛋白需求、分配时机、
  植物蛋白折算。回答「我该吃多少蛋白」「练后必须马上补吗」。
- `reference/减脂营养学-第3版.pdf` —— 教材，第 4 章讲能量缺口设定，
  第 7 章讲平台期。较长，建议按章节定位。

## 训练
- `training/新手周期化.md` —— 线性递进什么时候失效、怎么转双因子。
```

## 支持的文件格式，以及各自要不要装东西

**一句话：除了 PDF，常见格式都不用装任何东西。**

`.docx` `.xlsx` `.pptx` `.epub` 表面上是二进制，其实都是
**zip 包着一堆 XML** —— Python 标准库的 `zipfile` + `xml.etree` 就能把正文抠出来，
不需要 `python-docx`、`openpyxl`、`pandas` 里的任何一个。
这和项目「零依赖」的承诺是一致的。

### 不用装任何东西

| 格式 | 怎么读的 | 注意 |
|---|---|---|
| `.md` `.txt` `.csv` `.json` | 直接读 | **最推荐**，检索和引用都最准 |
| `.docx` | 解 `word/document.xml` | 只出正文。**图片里的文字读不到** —— 讲义类 docx 常有大量截图 |
| `.xlsx` | 解 `xl/worksheets/` + 共享字符串 | 出单元格值。公式只出结果、不出公式本身 |
| `.pptx` `.epub` | 同理，解内部 XML | |
| `.jpg` `.png` `.heic` | 直接看图 | 能看懂内容，但不好检索，量大时很占上下文 |

> macOS 上还有个更省事的办法：`textutil -convert txt -stdout '<文件>'`，
> 系统自带，`.doc` `.docx` `.rtf` `.odt` 都吃。
> **老式 `.doc`（二进制，非 zip）只能走这条** —— 标准库解不了。

### 需要装东西

| 格式 | 装什么 | 不装的后果 |
|---|---|---|
| **`.pdf`** | `brew install poppler` | **完全读不了**，一页也读不出来 |
| 扫描版 PDF（无文字层）| poppler + OCR | 装了 poppler 也只能渲染成图片来看，检索很差 |
| `.mp3` `.m4a` 等音频 | — | **不解析**。当备份留着就行，别指望从里面取内容 |

### 什么时候会来问你装不装

**只有三个条件同时成立**才会打断你：

1. 手头这个问题**确实需要**某份资料，不是顺手翻翻
2. 那份资料**当场读不了**（比如是 PDF，而本机没有 poppler）
3. **没有替代来源** —— 同一个结论在别的能读的资料里找不到

命中了就说清三件事：**装什么命令、这一份是什么、装完顺带解锁多少份**，
然后由你决定。三条纪律：

- **不自己装。** `brew install` 是对你系统的改动，得你点头
- **不在对话开头、不在扫索引的时候提。** 只在真的卡住的那一刻提
- **你说不装，也要能继续。** 会明说「这个结论少了哪份证据支撑」，
  或者请你自己转存一份（另存为 PDF/txt 都行），而不是假装读过

## 优先级：这些资料**不能**推翻的三件事

助手在用这里的资料时，遵守这个顺序：

```
安全边界  >  你的个人档案  >  这里的知识库  >  模型自己的通用知识
```

具体说：

1. **`knowledge/coach/safety-boundaries.md` 永远最高。**
   知识库里如果有「怎么调整某某药物剂量」「用某某补剂改善某项指标」这类内容，
   助手不会照搬 —— 用药和诊断一律转给医生。资料再权威也不例外。
2. **`profile/health-constraints.md` 次之。**
   知识库里推荐的动作，只要命中你记在那份文件里的禁忌，都会被挡下来。
3. **知识库高于模型的通用知识。**
   这是它存在的意义：你信任的资料优先于模型的泛泛之谈。有冲突时助手会
   明确说「按你知识库里的 X 说法」，而不是悄悄换掉。

放进来的资料如果和上面两条冲突，助手会**指出冲突**，而不是默默选一边。

## 加了资料之后

不需要跑任何命令，没有索引要重建。下次对话直接说：

> 我在知识库里加了一份讲蛋白质摄入的资料，之后聊饮食的时候参考一下。

或者让助手自己看：

> 看一下 knowledge/library/INDEX.md，然后按里面的方法评估我现在的饮食。
